### 1.5 三项设计决策

| 决策 | 选择 | 原因 |
|---|---|---|
| 检索融合 | **knn + BM25 双跑，应用层加权归一化融合** | 实测本机 ES 8.16 是 `basic` license，`rank.rrf` 返回 403 `current license is non-compliant for [Reciprocal Rank Fusion]`（`knn`+`query` 并发执行本身免费）。加权融合还顺带解决了「BM25 与 cosine 分数量纲不同」的问题 |
| ES 组件版本 | `indexer/es8`、`retriever/es8` 钉在 `v0.0.0-20260517075931-80b50f07e90b` | 更新的 `20260612`/`20260616` 把依赖抬到 `eino v0.9.2`，会顶掉全 workspace 的 `v0.8.7`。该版本依赖 `eino v0.6.0` + `go-elasticsearch/v8 v8.16.0`，与 ES 8.16 容器同版本 |
| 一个知识库一个索引 | ES 索引名 `kb_<uuid>`（uuid 去掉横线） | 与笔记一致，且删库=删索引，隔离彻底 |

### 1.6 三条执行入口

```text
POST       /api/v1/knowledge/:id/documents        写入：上传 → 切片 → 向量化 → PG+ES（异步）
POST       /api/v1/knowledge/:id/search           召回箱：不用模型，直接看检索结果
POST       /api/v1/agents/chat                    增强：检索 → 填 {ragContext} → 模型带引用回答
```

### 3.1 表结构（`model/knowledge.sql`）

只加表，不动 `agents`、`tools`、`llms`。全部 `IF NOT EXISTS`，可重复执行。

```sql
-- 知识库
CREATE TABLE IF NOT EXISTS knowledge_bases (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    deleted_at TIMESTAMPTZ,
```

### 4.2 配置结构（不依赖 `model`）

```go
type RetrieveConfig struct {
	Client *elasticsearch.Client
	Index  string
	TopK   int
	Filter []any          // ES filter 子句，来自 service 层的文档/元数据条件
	Embedder embedding.Embedder
	VectorWeight float64  // 0.7
	KeywordWeight float64 // 0.3

```

### 4.3 ES 索引 mapping（`EnsureIndex`）

```json
{
  "settings": { "number_of_shards": 1, "number_of_replicas": 0 },
  "mappings": {
    "properties": {
      "content":  { "type": "text", "analyzer": "ik_max_word", "search_analyzer": "ik_smart" },
      "content_vector": { "type": "dense_vector", "dims": 1024, "index": true, "similarity": "cosine" },
      "kb_id":    { "type": "keyword" },
      "doc_id":   { "type": "keyword" },
      "doc_name": { "type": "keyword" },
      "file_type":{ "type": "keyword" },
      "position": { "type": "integer" },
      "metadata": { "type": "flattened" }
    }
  }
}
```

实测：该 mapping 在本机 ES 8.16 全部可用，`ik_max_word` 已装（`_cat/plugins` → `analysis-ik 8.16.0`），`flattened` 类型的 `metadata.h1` 这种点路径可 filter。

> ⚠️ `dims` 必须与 `embedding_dimension` 一致，且**索引一旦创建就不能改**。改了 embedding 模型 = 重建索引，service 层换模型时必须同步 `EnsureIndex` 失败并给出明确错误。
>
> ⚠️ `ik_max_word` 在**写**侧、`ik_smart` 在**读**侧：写入时多切分（召回高），查询时少切分（精度高）。

### 4.4 切片（`chunker.go`）

笔记 07 只处理了 md 标题，本章把「切」做成一条链：

```text
1. 按文件类型选解析器（loader/file + parser/parser）
     md/txt/无后缀 → 纯文本（loader/file + parser.TextParser）
     docx          → docx parser（ToSections=true，按标题分段）
     html          → html parser（Selector=body）
     pdf           → pdf parser（ToPages=true）
2. 统一成 []Section{Text, Title, Chapter, Section}
3. 二次切片：单段字符数 > docChunkRunes(默认 500) 时按段落/句号切，重叠 docChunkOverlap(默认 60)
4. 元数据前缀（笔记 07 6.7 的做法）：命中率与语义完整性的关键
     「《<h1>》\n章节: <h2>\n小节: <h3>\n\n<正文>」
   前缀同时进入**向量文本**和 **ES content 字段**（两者一致，否则召回与展示会错位）
5. 补系统元数据：kb_id、doc_id、doc_name、file_type、position、chunk_id
```

> 💡 前缀进向量是笔记 07 就有的做法，本质是给「代词丢失」（笔记 2.2.1）打补丁——「它拥有500公里续航」这种切片，只有把所属标题拼进去，向量才知道「它」是谁。

### 4.5 写入（`store.go`）

用 `es8.NewIndexer`（**注意它是 `github.com/cloudwego/eino-ext/components/indexer/es8`，与 06 里 `core/tools` 那个 mcp 适配器包同名不同包，需 `es8Indexer` 别名避免混淆**）：

```go
indexer, err := es8Indexer.NewIndexer(ctx, &es8Indexer.IndexerConfig{
	Client: client, Index: index, BatchSize: 10,
	DocumentToFields: func(ctx context.Context, doc *schema.Document) (map[string]es8Indexer.FieldValue, error) {
		return map[string]es8Indexer.FieldValue{
			"content":        {Value: doc.Content, EmbedKey: "content_vector"},
			"content_vector": {},                       // EmbedKey 的容器键，由 indexer 回填
			"doc_id":         {Value: doc.MetaData["doc_id"]},
			...
		}, nil
	},
	Embedding: embedder,
})
ids, err := indexer.Store(ctx, schemaDocs)
```

> ⚠️ 06 的笔记代码里 `"doc_id": {Value: doc.MetaData["doc_id"]}` 依赖元数据先被赋值，本章把元数据在调用 `Store` **之前**补齐，并显式校验 `doc_id`/`kb_id` 非空，否则会写出无法被 filter 到的孤儿切片。

### 4.6 检索（`retriever.go`）——把笔记的 RRF 改成可用的融合

笔记 07 用的是 ES 原生 `rank.rrf`。**实测不可用**：

```text
POST /kb_xxx/_search  {"knn":{...},"query":{...},"rank":{"rrf":{}}}
→ 403 {"type":"security_exception",
        "reason":"current license is non-compliant for [Reciprocal Rank Fusion (RRF)]"}
```

基础 license 不允许 RRF。改为应用层融合，语义等价且可控：

```go
// 1. 向量召回：knn 内嵌 filter（pre-filter，先过滤再搜）
knn := types.KnnSearch{Field: fieldVector, QueryVector: vec, K: topK, NumCandidates: topK*10, Filter: filters}

// 2. 关键词召回：同一过滤条件下 BM25
must := []types.Query{{Match: map[string]types.MatchQuery{fieldContent: {Query: query}}}}

// 3. 一次请求双跑（ES 并行执行 knn 与 query，免费）
req := &search.Request{ Knn: []types.KnnSearch{knn}, Size: topK*2,
	Query: &types.Query{Bool: &types.BoolQuery{ Must: must, Filter: filters }} }

// 4. 应用层融合：分数归一化后加权
score = vectorWeight * normalize(cosineScore) + keywordWeight * normalize(bm25Score)
```

`normalize` 用**单次结果集内 min-max**，不是绝对分数——BM25 与 cosine 量纲不同，直接比大小必然偏向 BM25。

> ⚠️ 融合前必须先做**去重**（同一 `_id` 可能同时被 knn 和 BM25 命中）。笔记 07 的 `ResultParser` 里直接把 `hit.Source_` 反序列化后塞 `doc.MetaData`，重复命中会产出一条 `_score` 语义不明的记录；本章按 `_id` 合并取加权和后去重。
>
> 💡 保留 `Hybrid=false` 开关：纯向量模式用来做效果对比，也是本章验收时给用户看的「兜底召回」证据。

### 4.7 检索工具化 `NewRetrieverTool`

把「知识库检索」做成 `tool.InvokableTool`，用于两种场景：智能体**显式**调用、以及未来多知识库路由。

```go
// Info().Name = "kb_" + indexSuffix，例如 kb_7b25d157
// 参数：{"query": string, "topK": int}
// 返回：JSON [{content, doc_name, score, position}]
```

> 会话层默认**不用**它（见 7.1 的取舍），但保留并注册到工具表，作为「模型想主动再查一次」的出口。

## 六、业务层 `app/internal/knowledge/service.go`

### 6.1 创建知识库

```text
name 非空 → embeddingModelProvider/Name 必填
→ event.Trigger("getEmbeddingConfig", shared.LLMParams{UserID, ModelType: embedding, Provider, Model})
→ 校验返回的 provider config 是 active
→ 探针调用 EmbedStrings(["dimension probe"]) → 得到 EmbeddingDimension
→ IndexName = kb_<uuid 无横线>
→ core/rag.EnsureIndex(dims)   // 建索引失败则回滚 DB 插入
→ 落库
```

维度**必须探针实测**，不能写死 1024：同一 provider 的不同模型维度不同（`bge-m3` 1024、`text-embedding-3-small` 1536），写死就是未来必然的 400。

> ⚠️ 建索引用「先建 ES 索引，后落 PG」的顺序：反过来的话，PG 里会出现一个永远检索不到的库。

### 6.2 上传文档（异步流水线）

```text
c.FormFile("file") → 扩展名白名单（md/txt/docx/pdf/html）
→ sha256 → 同库查重（4006）
→ 落 documents 记录（status=pending, size, file_type）
→ 立刻返回 DocumentResponse（前端拿到 id 开始轮询）
→ goroutine（context.Background()，不要用请求 ctx，笔记 07 已踩过）：
     status=processing
     解析（core/rag.Parse）
     切片（core/rag.Split）→ 前缀 → 元数据
     向量化 + 写 ES（core/rag.NewIndexer/Store）
     切片批量写 PG（含 es_id）
     status=completed / failed（failed 时写 error_message）
     updateDocumentCount / chunk_count
```

> ⚠️ 全库重算会 O(n) 更新每条切片（笔记 07 的 `meta["h1"]` 在循环里被反复改写后仍指向同一个 map：`currentMeta := chunkMetadata[i%len(chunkMetadata)]` 在多块场景下会串味）。本章每个切片在 `Split` 阶段就拿到**自己的**深拷贝元数据，写入前不再复用。

### 6.3 搜索知识库

```text
校验 kb 属于当前用户 → 构造 RetrieveConfig（Embedder 由 kb 的配置事件解析）
→ core/rag.Retrieve
→ 命中 _id = 切片 uuid → PG 回查 chunk + document（拿文件名/类型/时间）
→ SearchResponse{ query, results[], total, took, kbId, mode: "hybrid|vector" }
```

`filter`（请求体里的过滤条件）第一版支持 `filter.documentIds`（限定文档）与 `filter.metadata`（点路径等值）。透传成 ES `terms` / `term` 子句，写进 knn 的 `filter`。

### 6.4 删除 / 重索引

| 动作 | 链路 |
|---|---|
| 删知识库 | 若被 `agent_knowledge_bases` 引用 → 4008；否则删 PG（kb+documents+chunks）→ `DropIndex(kb_xxx)` |
| 删文档 | 事务：删 chunks → 删 document → 更新统计；随后 `DeleteByQuery(doc_id.keyword)` 清 ES（ES 失败只告警，不回滚，靠重索引兜底） |
| 重索引 | status=processing → 删该 doc 的 ES 切片 → 重新解析入库（源文本取自 `document_chunks`，因为第一版不落对象存储） |

> ⚠️ 第一版不落对象存储，所以「重索引」依赖 PG 里的切片文本；如果用户改了切片参数再重索引，结果会基于**旧切片拼接**而不是原始文件。文档里必须写清这个限制，或把 `storage_key` 真正接上 `thunder/upload`（下一章）。

## 七、会话层 `app/internal/agents/service.go`

### 7.1 `{ragContext}` 装配（本章核心）

```text
GetAgentWithKnowledgeBases（JOIN 过滤 status=enabled）
→ 逐个知识库检索（query = 用户这条 message，TopK=5）
→ 按分数合并、截断到 ragTopK(默认 5) / ragMaxRunes(默认 2000)
→ 拼成：
   [1] 《MCP 工具》/章节: 三、模型层  （来源：MCP测试文档.md）
   <片段正文>
   [2]
→ buildSystemPrompt 的 {ragContext} 用该文本替换（06 里它是 ""）
```

**取舍：默认用「会话开始前隐式检索」，不用「模型调工具检索」。**

理由：本机对话模型是小模型（`deepseek-v4-flash`），06 的验收已经记录过「工具多、描述长时模型会选错或不调用」；知识库检索是**每轮都要发生**的基础动作，交给模型自己决定等于把召回率交给概率。两者并用会浪费一轮 `maxToolRounds`。

同时保留显式工具 `kb_<suffix>`：模型判断首轮片段不够时可以自己再查一次。

### 7.2 生命周期与超时

```go
// AgentMessageStream 内，模型调用之前
ragCtx, cancel := context.WithTimeout(ctx, 6*time.Second)
defer cancel()
ragContext := buildRagContext(ragCtx, agent, request.Message)
```

```text
prepareAgentTools ─▶ buildRagContext ─▶ WithTools ─▶ Stream ─▶ ToolCall ─▶ …
      │ MCP Client 开        │ 检索（embedding HTTP + ES）                    │
      └──────────────────── defer Close ──────────────────────────────────────┘
```

> ⚠️ 检索失败**不能阻断对话**：记录告警、`{ragContext}` 留空、照常回答。知识库是增强不是前提（与 06 里「单个 MCP Server 连不上只跳过」同一原则）。

### 7.3 引用透传

命中片段记录 `doc_name` / `position`，SSE 里可选推一条 `references` 消息（`core.AgentMessage` 加 `references` 字段，`omitempty`）。本章实现后端字段与推送，前端渲染留到下一章——避免这一章同时改前端大块结构。

## 十一、常见问题排查（预判）

| 报错 | 原因 | 解决 |
|---|---|---|
| `current license is non-compliant for [RRF]` | 用了 ES 原生 `rank.rrf` | 本章已改应用层融合；不要照抄笔记 07 的 `rank` 段 |
| `failed to create ES8 indexer: mapping definition ... dims` | `embedding_dimension` 与模型实际维度不符 | 删库重建；创建时用探针实测维度 |
| `insufficient_quota` / 401（embedding） | 配置的 API Key 无效或余额不足 | 校验 `provider_configs.api_key`，日志里不打印 key |
| 上传后 status 一直 `processing` | goroutine panic / 上下文被取消 | 用 `context.Background()`；`recover()` 后写 `failed` + `error_message` |
| 检索永远只返回 BM25 命中 | `content_vector` 没写进去（`EmbedKey` 配错） | 对比 `_search {"size":1}` 看 `_source` 里有没有 `content_vector` |
| 中文检索命中率差 | `ik` 插件没装 / 用了 `standard` analyzer | `GET _cat/plugins` 必须是 `analysis-ik 8.16.0` |
| `go test ./...` 根目录失败 | 根目录不是模块 | 按模块列出（06 已记录） |

## 十二、遗留事项

| 项 | 风险 | 建议 |
|---|---|---|
| 未落对象存储 | 重索引依赖 PG 里的旧切片文本；原文丢失后无法真正重切 | 接 `thunder/upload`（本地/OSS），`storage_key` 落地 |
| 上传接口无大小/类型限制的硬约束 | 大文件 OOM、恶意文件 | `maxUploadMB` + 白名单 + 后续异步队列 |
| 同步检索在请求路径上 | embedding HTTP + ES 增加 ~200-800ms | 后续加 Redis 缓存（key=kb+query hash） |
| 单库单索引、无权限隔离 | 同用户跨库不可见已做，跨用户共享库未做 | 需要时按 `creator_id` 派生读权限 |
| 切片质量无量化指标 | 只能靠肉眼 | 后续加「检索命中率」离线评估脚本（本章只留 `/chunks` 接口） |
